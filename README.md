# 向前 · Personal AI Executive Assistant

> 一个自己每天真实在用的个人 AI 执行助理：网页端 + 原生 Android + 云端网关三端联动，
> 支持多轮对话、每日动态计划、任务计时、主动唤醒与提醒、记忆整理和使用数据洞察。

## 功能特性

- **多线程 AI 对话**：普通助手 / 每日规划 / 项目助理等会话模式，Agent 工具调用（闹钟、任务、重排计划、记忆沉淀），失败运行以错误卡片原样呈现并可与服务端持久化结果对账。
- **动态日程计划**：根据睡眠时间、任务队列、不可用时段与缓冲自动排布今天做什么；完成/外出/疲惫等一句话即可触发重排。
- **主动唤醒（Proactive）**：手机连续使用超时、到期复查、系统闹钟、30 分钟心跳等事件统一为信号，幂等键去重后交给 AI 自主判断"是否值得打扰用户"。
- **手机使用洞察**：基于 UsageStats 的前台会话统计、每日限额提醒、睡眠/起床时间推断（仅作候选，不覆盖用户设置）。
- **记忆整理**：重要对话沉淀为记忆条目，每日定时归档为记忆摘要。
- **云端同步**：Supabase 账号登录 + 请求级状态快照合并，多端（网页 / 手机）读写同一份计划。

## 架构

```
┌────────────────┐   HTTPS   ┌─────────────────────────────┐
│  Android App   │──────────▶│  Caddy 反向代理（令牌注入）  │
│ Kotlin/Compose │           └──────────────┬──────────────┘
└────────────────┘                          │
┌────────────────┐   HTTP    ┌──────────────▼──────────────┐
│   Web 管理端   │──────────▶│  Node/Express AI 网关        │
│  React + Vite  │           │  ├─ Skills/Tools 注册表      │
└────────────────┘           │  ├─ 状态存储（原子变更+审计）│
                             │  ├─ 多提供商模型接入         │
┌────────────────┐           │  └─ 主动信号 / 心跳调度      │
│ 自建模型网关    │◀──────────└──────────────┬──────────────┘
│ (多上游聚合)    │                          │ SQL（可选云同步）
└────────────────┘           ┌──────────────▼──────────────┐
                             │  Supabase / 本地 JSON 状态   │
                             └─────────────────────────────┘
```

- **服务端**：Node.js + Express，`server/` 约 6000 行
- **网页端**：React + Vite，`src/`
- **Android**：Kotlin + Jetpack Compose，前台服务承载使用监控与心跳

## 技术亮点

### Agent 运行时：模型只提议，状态唯一落点

```
消息 → 上下文组装 → 模型 JSON → 动作规范化 → 原子执行 → 工具结果 → 回复 + 审计日志
```

- Skills 描述场景行为，Tools 是确定性操作，模型通过 `actions` 提议，**只有状态存储能真正改数据**，且每次变更有审计日志；
- 设备侧动作（设闹钟/延后提醒）作为 `deviceActions` 单独返回，由手机本地执行并回报结果，避免"模型说做了就算做了"。

### 主动唤醒系统：一整套"打扰的艺术"

- 五类信号（连续使用/到期复查/时间/任务/计划偏差）归一为统一信号信封；
- 三层防误扰：**幂等键去重**（信号信封 + 内容摘要）、睡眠窗口、AI 自主判断（只有调用 `send_proactive_message` 才算真正投递）；
- **心跳保活链**：系统闹钟每 30 分钟拉起监控服务，对抗国产 ROM 游戏模式对前台服务的冻结；闹钟广播由系统投递，不被拦。

### 性能优化：76 秒 → 1.9 秒

聊天图片曾以 base64 内联在状态文件里，641 条消息把状态文件撑到 20 MB：

| 指标 | 优化前 | 优化后 |
|---|---|---|
| 状态文件体积 | 20.6 MB | 3.0 MB |
| 打开主对话 | 10.7 MB / 76 s | 183 KB / 1.9 s |
| 全量状态读取 | 20.2 MB / 137 s | 2.7 MB / 7.2 s |
| 聊天页 5 秒轮询 | 全量 10.7 MB/次 | 仅增量（通常 0 条） |

手段：附件落盘 + 消息只存网关文件引用 + 按消息 ID 的增量拉取（created_at 只有分钟精度，不能用时间戳做水位）。

### 可靠性细节

- 幂等键贯穿主动信号全链路（设备生成 → 网关 claim → 运行完成）；
- 状态读取即修复（repair），写入走临时文件 + 原子 rename；
- Android 侧本地去重（SharedPreferences 持久化幂等键），网络失败自动重试。

## 安全模型

- 所有模型密钥只存在于服务端，**APK 与网页端不内置任何模型 key**；
- 网关访问通过反向代理注入的私有令牌 + 本地/同源请求白名单控制；
- 附件文件服务严格校验文件名模式，杜绝目录穿越；
- `.env.local`、`local.properties`、状态数据均被 `.gitignore` 排除。
